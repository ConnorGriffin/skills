skills

A portable skill pack for coding agents. Twenty-seven skills that turn a vague request into tracked work, that work into a reviewed pull request, and that pull request into merged history — with the decisions written down as they are made.

The pack is organised by how much of a job a skill owns. Start at a workflow when you do not yet know what kind of problem you have; reach for a driver when the work has a lifecycle; load a tool when you need one reference or one pass. Skills name each other freely — the map below is every one of those references.

workflows

2

Front doors. You name the situation; the workflow classifies it and routes to exactly one specialist skill — it does no work itself.

  • reviewFront door for review of any kind — code, a plan, a document that needs named reviewer perspectives, or pending changes with a security question.
  • scopeTriage front door for work that isn't ready to build.

drivers

6

Lifecycles. A driver owns a piece of work from arrival to done, through named verbs and state it records outside the conversation.

  • epicMaintain an epic ledger and work clear child tickets through a GitHub-backed planning lifecycle.
  • implementImplement a piece of work based on a PRD or set of issues.
  • openspec-adoptAdopt OpenSpec in a repo that lacks it: scaffold the openspec/ layout, write baseline specs describing the system as it exists today (from code, docs, and git history), and deliver the whole thing as a documentation-only PR.
  • orchestrateFlip the session into coordinator mode — the parent agent plans, scopes, reviews, and ships, but delegates all real work (exploration, implementation, review, fixes) to sub-agents routed by an empirically benchmarked model capability table.
  • ticketDrive one tracked ticket from arrival to resolution through four verbs: triage, start, revise, finalize.
  • ui-craftLifecycle for user-facing surfaces — revise a shipped surface in the running app, lock a greenfield visual spec, build to a lock, critique/audit/polish a UI, or re-settle a locked term.

tools

19

References and single passes. Load one for its vocabulary, its checklist, or one bounded job, then get on with the work.

  • cbm-onboardRegister maintained or ephemeral Git checkouts with codebase-memory-mcp, keep long-lived indexes current through non-clobbering Git hooks, and tear down ephemeral indexes by exact deterministic identity.
  • ci-designVocabulary and principles for well-designed CI.
  • cleanClean the current branch's diff without changing behavior — naming, dead code, duplication, and the charter's deep-module rules — in one pass, then stop.
  • code-reviewReview the changes since a fixed point (commit, branch, tag, PR, or merge-base) on two axes — Standards (does it follow this repo's documented rules?) and Spec (does it do what the originating issue asked?).
  • codebase-designShared vocabulary for designing deep modules.
  • codebase-memoryUse the codebase knowledge graph for structural code queries, trace call paths and dependencies, inspect architecture, assess change impact, or activate the bundled Claude Code discovery hooks.
  • domain-modelingBuild and sharpen a project's domain model.
  • drive-local-webappLaunch or connect to a local development web server and drive it with a reusable headless-Chromium command interface.
  • handoffProduce a decision-safe handoff for a fresh agent.
  • persona-reviewConvene a small panel of persistent reviewer personas (curated colleague-likenesses plus invent-on-demand) to review a document cold, in character, then synthesize a panel verdict.
  • plan-reviewAdversarially review a plan, work order, spec, or agent brief before anything gets built.
  • pr-bodyWrite a pull-request body and score it before the PR is opened, or audit an existing PR's body against the same rubric.
  • preflightUse when a plan, spec, work order, or process doc is drafted and about to enter review or execution — grounds its facts, spikes its first hour, and single-sources its rules so review rounds start deep instead of shallow.
  • prototypeBuild a throwaway prototype to flesh out a design — a runnable terminal app for state/business-logic questions, or several radically different UI variations toggleable from one route.
  • researchInvestigate a question against high-trust primary sources and capture the findings as a Markdown file in the repo.
  • say-lessShape every response for a reader who wants the answer first and nothing after it.
  • spin-worktreeCreate an isolated Git worktree for issue, pull-request, branch, or parallel agent work without editing the control checkout.
  • tddTest-driven development.
  • writing-for-agentsReference for writing and editing skills well — the vocabulary and principles that make a skill predictable — plus a doctor verb that audits the loaded skill and CLAUDE.md/AGENTS.md estate.
