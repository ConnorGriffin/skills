# OpenSpec versus ADR workflow

## Decisions

- Route this work to `research` — the first uncertainty is what OpenSpec provides in practice and whether those capabilities address a gap in the existing ADR workflow. `inline`

## Open questions

- What lifecycle, to-do tracking, change archival, and review/merge integration does OpenSpec provide?
- Which of those capabilities are absent from the current ADR system in the repos under consideration?
- Does the added process improve traceability enough to justify adoption and migration overhead?
- Should adoption, if worthwhile, be repo-wide or limited to change-heavy repos?

## Spawned tasks

- Research OpenSpec’s documented workflow and compare it with ADRs and the requested pre-merge archival lifecycle.
